# 家里的旁路由（QNAP NAS）

让家里所有设备（电视、游戏机、没装 FlClash 的手机）都用同一套分流：必须用中国 IP 的服务走回国节点，其余直连，并去广告。分流规则和 FlClash 设备完全一样，都由 `override.js` 生成。

```text
设备 ──网关/DNS──▶ NAS 上的 Mihomo 容器 (192.168.50.2) ──▶ 华硕路由器 (192.168.50.1) ──▶ 外网
                                         └──回国流量──▶ 机场节点
```

- `config.yaml`：由 `tools/build-router-config.mjs` 从 `override.js` 生成，不要手改。它和 FlClash 设备的唯一区别是：机场节点来自订阅（proxy-provider），以及 TUN、DNS、嗅探、控制面板这些网关设置。订阅里只用名字带 `🇨🇳`、`回国`、`大陆` 或 `内地` 的节点，同时卖出国节点的机场（例如 EdNovas）也能直接用；换成名字里没有这些标记的机场时，要改 `tools/build-router-config.mjs` 里的 `filter`。
- `compose.yaml`：粘贴到 Container Station 的应用配置。容器启动时从 `main` 下载 `config.yaml`，填入订阅地址和面板密码，用 `mihomo -t` 检查后运行。之后每 5 分钟再下载一次，有变化就换上新配置并重启容器。GitHub 访问不了时，继续用上一份能用的配置。

## 一次性准备（已完成）

1. 华硕路由器“内部网络 → DHCP 服务器 → 手动指定 IP”：`192.168.50.2` 预留给 MAC `02:42:C0:A8:32:02`（容器），NAS、工作站、摄像头绑定各自现在的地址。
2. NAS 的 Adapter 1 改成静态 IP：`192.168.50.30`，网关和 DNS 都是 `192.168.50.1`。NAS 自己不能走旁路由：macvlan 容器和宿主机之间不通。
3. 华硕路由器关闭 IPv6，避免设备通过 IPv6 绕开旁路由。

## 部署

1. 打开 Container Station → 应用程序 → 创建，名称填 `mihomo-router`，粘贴 `compose.yaml` 的全部内容。
2. 改两处：
   - `SUBSCRIPTION_URL`：机场订阅链接，和 FlClash 里的一样。只写在 NAS 上，不要提交到仓库。
   - `CONTROLLER_SECRET`：控制面板密码，用 `openssl rand -hex 16` 的输出。
   - Compose 会展开 `$`，即使在引号里：值里的每个 `$` 写成 `$$`，每个 `'` 写成 `''`。
3. 核对 `parent: eth0`：它是 Adapter 1 在系统里的名字。以后如果给 NAS 建了虚拟交换机，这里要改成 `qvs0`。
4. 创建并启动。第一次启动要下载镜像、规则集和面板，约一两分钟。
5. 浏览器打开 `192.168.50.2:9090/ui`。后端地址就是这个页面所在的 `192.168.50.2:9090`，密钥填 `CONTROLLER_SECRET`。能看到 `回国节点` 和机场节点就说明订阅已经加载。

## 先用一台设备试

在一台手机或电脑的 Wi-Fi 设置里改成手动：IP 保持原来的，路由器（网关）和 DNS 都填 `192.168.50.2`。然后检查：

- 普通网站、YouTube 正常，速度和改之前差不多（测速对比一下，NAS 的 CPU 要处理全部流量）。
- B 站番剧、腾讯视频、QQ 音乐能播放：说明回国分流生效。
- 面板的“连接”页能看到这台设备的连接和命中的规则。

试完把这台设备改回自动。

再从 QTS 菜单重启一次 NAS，确认 `mihomo-router` 自己起来了（面板能打开，试用的设备能上网）。周日凌晨的固件更新也会这样重启。

## 全家切换

华硕路由器 → 内部网络 → DHCP 服务器：

- 默认网关：`192.168.50.2`
- DNS 服务器 1：`192.168.50.2`
- 同步广播路由器 IP 作为 DNS：否（否则设备会绕过旁路由直接问路由器）

保存后，设备在续租时（最长 24 小时）换到旁路由；重连 Wi-Fi 会立刻生效。

不要走旁路由的设备，在设备上手动设置 IP，网关和 DNS 填 `192.168.50.1`：

- NAS 本身（已经是静态 IP）。
- 摄像头：Reolink App → 设备设置 → 网络信息 → 静态，IP 填 `192.168.50.180`。
- 公司电脑等不希望经过代理的设备。

路由器上做了端口转发的设备（比如工作站的 SSH `192.168.50.5:2222`）可以继续走旁路由：把它写进 `compose.yaml` 的 `DIRECT_REPLIES`（多个用空格分开）。否则从外网连进来时，它的回复会进 Mihomo 并被丢掉，因为 Mihomo 没见过这条连接的开头。写进去以后，这些回复直接交回路由器，这台设备的其他流量照样走旁路由。以后新增端口转发，也要加到这里。

在家时，手机和电脑上的 FlClash 可以关掉：旁路由已经按同样的规则分流。

## 日常怎么用

都在面板 `192.168.50.2:9090/ui` 里操作：

- **机场挂了**：不用处理。回国节点全部不通时，必须回国的服务自动改走直连，恢复后自动切回。
- **出站模式**：规则（平时）、全局（所有流量回国，应急）、直连（回国机场时好时坏、来回切换的时候）。切换后在“连接”页关掉旧连接，或者重开 App。切换只到下一次重启为止：NAS 重启或 `main` 上的配置有更新时，旁路由会回到“规则”。
- **固定节点**：在 `回国节点` 组里点一个节点。它挂了会自动换到最快的节点，恢复后再用回它。注意：点组的“测速”按钮会取消固定（Mihomo 的行为），只给单个节点测速不会。
- 规则文件 `rules/*.txt` 改动后，旁路由和 FlClash 设备一样最多约 1 小时生效，`router-mode refresh` 可以让旁路由立刻生效；`override.js` 改动合并后约 5 到 10 分钟生效（GitHub 缓存加上每 5 分钟一次的检查），旁路由会重启一次。

不方便开面板时（例如在外面用手机 SSH 到家里的电脑），用 [`router-mode`](router-mode)，局域网里有 `sh` 和 `curl` 的机器都能用：

```bash
router-mode           # 当前模式和回国流量走哪个节点；机场全挂时显示 DIRECT
router-mode direct    # 直连；rule 回到规则；global 全部回国
router-mode refresh   # 立刻重新下载全部规则列表和订阅
```

安装：把它复制到 `~/.local/bin/` 并 `chmod +x`，面板密码写进 `~/.config/router-mode/secret` 并 `chmod 600`。

## 出问题时

- **旁路由挂了，全家上不了网**：华硕路由器 DHCP 服务器里清空“默认网关”和“DNS 服务器 1”，“同步广播路由器 IP 作为 DNS”改回“是”，保存后重连 Wi-Fi。设备回到直接走路由器。
- **NAS 重启**（固件更新已改为每周日 04:00）：期间全家断网几分钟，容器会随 NAS 自动启动。
- **看日志**：Container Station → 容器 → mihomo-router → 日志。`The new config does not parse; keeping the old one.` 表示仓库里的新配置有问题，旁路由还在用旧配置。
- 订阅拉取失败时，日志里的 `[Provider] airport pull error` 这类行会带完整的订阅链接。分享日志或截图前先把链接删掉。

## 安全

- 面板和 DNS 只在家里局域网可用。路由器上不要为 `192.168.50.2` 做任何端口转发。
- 订阅地址和面板密码不在仓库里，只在 NAS 的应用配置里。订阅出错时链接会出现在容器日志和面板的日志页，所以面板密码也等于能看到订阅链接。
- 升级 Mihomo：在仓库里改 `compose.yaml` 的镜像版本并合并 PR（CI 会用新版本跑端到端测试），然后在 Container Station 里把应用配置的版本号改成同样的值。
